🚀 O QUE CADA WORKFLOW FAZ?

┌─────────────────────────────────────────────────────────────────────────┐
│ 🔄 AUTO-INCREMENT (auto-increment.yml)                                  │
│                                                                          │
│ Dispara: Push para main                                                 │
│ Faz: Incrementa build number automaticamente                            │
│                                                                          │
│ Exemplo:                                                                 │
│   • Você faz merge de PR                                                │
│   • Versão vai de 1.0.0+5 → 1.0.0+6                                     │

└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ 🚀 BUILD & RELEASE (release.yml)                                        │
│                                                                          │
│ Dispara:                                                                 │
│   • Tag de versão (v1.0.0, v1.1.0)                                      │
│   • Manualmente via GitHub Actions UI                                   │
│                                                                          │
│ Faz:                                                                     │
│   • Incrementa versão (patch/minor/major)                               │
│   • Roda testes                                                          │
│   • Gera .aab assinado                                                   │
│   • Cria release no GitHub                                              │
│   • Upload para Play Store (opcional)                                   │
│                                                                          │
│ Como usar:                                                               │
│   • GitHub → Actions → Run workflow                                     │
│   • Ou: git tag v1.1.0 && git push origin v1.1.0                        │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ 🧪 CI - PULL REQUEST (ci.yml)                                           │
│                                                                          │
│ Dispara: PR para main/develop                                           │
│                                                                          │
│ Faz:                                                                     │
│   • Valida formatação                                                    │
│   • Roda flutter analyze                                                │
│   • Roda testes                                                          │
│   • Testa build                                                          │
│                                                                          │
│ Benefício:                                                               │
│   • Sabe se PR está OK ANTES de mergear                                 │
│   • Previne bugs em produção                                            │

💡 FLUXO DE TRABALHO IDEAL
═══════════════════════════════════════════════════════════════════════════

Desenvolvimento diário:
  1. Criar branch: feature/nova-funcionalidade
  2. Desenvolver
  3. Abrir PR → ✅ CI valida automaticamente
  4. Revisar e aprovar
  5. Merge → ✅ Auto-increment roda
  6. Versão incrementada automaticamente!

Fazer release:
  1. Decidir tipo: patch, minor ou major
  2. GitHub Actions → Run workflow → Selecionar tipo
  3. Aguardar 5-10 minutos
  4. Baixar .aab dos artifacts
  5. Upload na Play Store
  6. Publicar! 🎉

🔧 INSTALAÇÃO

# 1. Copie os arquivos para seu projeto
cd seu-caminho/witchy-app
cp -r github-actions-setup/.github .
cp -r github-actions-setup/scripts .
chmod +x scripts/bump_version.sh

# 2. Configure permissões no GitHub
# Acesse: https://github.com/laylamonteiro/witchy-app/settings/actions
# Marque: "Read and write permissions"
# Marque: "Allow GitHub Actions to create and approve pull requests"
# Salve

# 3. Commit e push
git add .github/ scripts/
git commit -m "🚀 Adiciona CI/CD workflows"
git push origin main

# 4. Teste!
# Acesse: https://github.com/laylamonteiro/witchy-app/actions
# Run workflow manualmente

❓ PERGUNTAS FREQUENTES
═══════════════════════════════════════════════════════════════════════════

P: Preciso configurar algo no código do app?
R: Não! Os workflows funcionam com o app como está.

P: Vai fazer upload automático para Play Store?
R: Não por padrão. Você precisa configurar o Service Account.
   Ver: GITHUB_ACTIONS_SETUP.txt seção 3.

P: Quanto custa?
R: ZERO! GitHub Actions é grátis para repositórios públicos.
   Para privados: 2000 minutos/mês grátis (mais que suficiente).

P: E se eu não gostar?
R: Só deletar a pasta .github/workflows. Pronto!

P: Posso personalizar os workflows?
R: Sim! Todos os arquivos .yml são editáveis.

P: Funciona para iOS também?
R: Estes workflows são para Android. iOS precisa de Mac runner (pago).

P: Como desabilitar um workflow?
R: GitHub → Settings → Actions → Disable específico workflow
